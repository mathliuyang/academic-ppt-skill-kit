# 交付与验收

## 成品和工作材料

新报告默认交付可编辑 PPTX 及配套 PDF、Word 逐字稿和大字纯讲稿 PDF；按用户需求增减，独立 PNG 和 Word 原排版 PDF 需要时另交付。讲稿页号与 PPT 对齐，所有口述正文同步到同一份逐页数据。既有报告的局部修改只更新受影响的交付物，按下文“局部修改与复核复用”确定范围；讲稿内容未变时不重建讲稿。制作及修订阶段可在工作目录暂存版本，确认定稿后的保留范围按下节整理。

制作及核验阶段保留逐页数据、图源记录及检查结果，不把检查清单、编程过程、内部提示或制作说明放入观众页面和朗读正文。Word 可以包含独立提示，其配套 PDF 保留 Word 原排版；大字纯讲稿 PDF 去掉这些提示，保留正文和页号。短讲稿尽量排成两页 A4、加粗关键词及重要数据；长稿增加页数，避免删除正文或缩成小字只为满足两页。

只有用户要求或实际采用逐页生图时才生成相应预览；按用户需要交付。真实生图与最终 PPT 渲染区分保存，PPT 渲染不能冒充生图。规范见 `imagegen-preview-first.md` 与 `preview-data.md`。

既有报告修订可沿用真实历史预览作内部结构参考，制作及核验时保留历史工具记录与图像，不改写历史内容。交付包仅包含本轮认可的成果，过时设计参考不进入更新版ZIP；不得把历史预览称作本轮重新生成的设计。用户要求定稿清理时，以其保留范围为准。

## 项目日期与统一目录

- 首次创建工作项目时，立即用 `YYYYMMDD_项目名称` 命名主目录。例如2026年10月24日开始制作的项目使用 `20261024_含氟聚芳基哌啶鎓膜文献汇报`；日期为项目创建日，采用用户本地日期，不能使用论文发表年份或预计汇报日期。
- 同一项目从制作到定稿始终沿用这一日期。后续续做、修订、复制、迁移、改名或清理目录时，不把前缀换成操作当天的日期，也不另建一个当天日期的项目目录来放同一项目的新版本。
- 为没有前缀的旧项目补日期时，核对最初工作目录的创建记录或首次制作请求。已知目录是后来整理或复制生成的，应追溯原项目开始日期，不直接采用该目录新的文件系统创建时间；仍无法确定时再询问用户。已有可信日期前缀的项目直接沿用。
- 各篇正式报告统一使用下列三个分类目录。日期前缀只加在项目主目录上，分类目录保持相同名称；正式文件按材料用途放入对应位置。制作中的临时材料在定稿后按清理范围移除，不作为第四类正式交付目录继续保留。单独建立的公共资料目录按其自身首次建立日期命名，如 `20261024_公共资料`。
- 此目录结构用于新项目和获授权的整理。既有项目沿用其来源与命名，不因参考案例曾使用其他目录就直接迁移。可选的版式对照图放在 `01_汇报文件/版式对照/` 或工作资料中，`03_论文资料` 的用途保持不变。

```text
YYYYMMDD_项目名称/
├─ 01_汇报文件/    PPTX及同名PDF，含需要保留的答疑汇报
├─ 02_讲稿文件/    Word及同名PDF、大字讲稿和答疑讲稿
└─ 03_论文资料/    论文原文及已取得的补充材料
```

## 正式命名与定稿整理

- 正式目录沿用项目首次创建时的 `YYYYMMDD_项目名称`，项目名称用报告主题表述。文件名简洁、正式、直接，采用“汇报人_论文主题_文献汇报”或“汇报人_论文主题_讲稿”等材料类型。去掉“自然衔接版”“口语修订版”“精修”“定稿”“最终最终”及V数字等过程或版本标签。大字讲稿按用途命名，不把它写成新的修改版本。
- 默认提供 PPTX 的同名 PDF 和大字讲稿 PDF；用户要求 Word 原排版 PDF 时再提供。PPT的PDF按每页一张幻灯片导出，保持页面比例；Word的PDF保留正文、提示、页眉页脚和分页等原排版。大字纯讲稿PDF作为另一种阅读用途保留。修改PPT或Word后同步更新对应PDF，不用旧PDF冒充新文件的配套版本。
- 当本次任务包含定稿整理时，将认可文件归入正式成品目录，每种用途只保留一套；局部修订不因此启动目录迁移或清理。用户要求只留成品时，清理本次报告的旧版本目录、过程稿、临时构建文件、核验副产物及重复压缩包，不另建“备份旧稿”继续堆积。用户明确要求保留的素材、预览或工作数据按其范围保留。
- 清理前先确认正式文件齐全、可打开，配套PDF页数和内容正确，并按本轮修改范围完成下文要求的视觉复核。只改路径或文件名时核对内容哈希，避免在整理过程中改动已认可的正文与版式。原始论文、补充材料及模板保留在来源资料位置，必要时先移出待删除的工作目录。
- 删除范围仅限本次报告可确定的旧版和过程材料；不扩大到其他论文、他人文件、原始参考或共享运行库。执行前核对绝对路径及目录链接；Windows工作目录中的junction等链接先仅移除链接本身，未处理链接时不递归删除或移动其父目录，避免沿链接进入共享目录。整理完成后检查正式目录无旧标签、无遗漏PDF、无残留过程文件，再给出新的成品入口。

## 内容检查

- 将每页结论和关键数值与论文相应位置对照，检查单位、比较对象、尺度、方向及测试条件。检查作者姓名、称谓、团队、日期和 JIF 年份；国内作者的中文姓名有官方来源和身份对应依据。
- 检查实际显示的封面指标已核实且标明体系、年份和必要学科；未核实项目从观众页面省略，metadata保留检索状态。不为凑齐指标显示未知字段或占位词。
- 查看联网检索记录：已检查出版商论文页、补充材料/数据/视频入口，并考虑直接相关的官方研究解读或背景资料。选入的附件和视频支持具体讲述；未找到、不可访问或不适用均如实记录，不把“找到链接”写成“已取得文件”。
- 图源记录与实际图片一致；关键子图含必要的坐标、图例、颜色、比例尺和刻度，画面不拉伸。区分原文实验证据、外部相关研究和辅助示意。
- 逐页正文与页面相符，跨页承接自然；总结覆盖主要贡献，避免片面、堆叠和重复。按目标时长检查视频、翻页和停顿是否计入。
- 搜索来源姓名、单位、实验室文字、错误校训和旧论文关键词，包括母版／布局继承层、隐藏对象和备注。身份采用当前认可报告或已选档案；既有报告保留已记录的品牌素材版本，不因纯布局修订升级到档案最新版本。

- 生图与重建保持原模板的高信息密度、充实框架、字体字重、主辅图比例及合理细框/短蓝标题分组。检查是否靠大字号、大图加空泛两句、重复标签撑页，或缺少理解所需的条件/对照；同时检查重复全文来源、内部过程文案及无依据的成本风险评论。按具体内容判断，不作机械禁词扫描。

## 编辑性和同步检查

检查文字、表格、箭头和框体为可编辑对象，科学图片为独立组件；不能仅凭 PPTX 扩展名称其可编辑。复杂图片内部不可逐项编辑的限制应准确描述。

品牌在实际页面检查完整性、比例、色彩、读字与继承层。按本次适用的授权素材核验。

仅在本次真实品牌已确定且要求每页展示时，检查所有页面的完整logo，含封面、章节、结束页，并传 `--require-every-slide-brand` 及实际PPT/品牌档案核验覆盖。身份未知或无品牌时不捏造或沿用案例标识。按所选参考系列检查公共框架：正文、总结和讨论页共用同一底线、页码和品牌布局，概述按需使用预留位置；封面、结束和备份可按各自用途采用系列中已定义的样式。逐页生成图偶发的页脚或校徽漂移不能自动成为新页型。统一公共框架不要求内容区使用相同大框。

检查实际继承层及绘制层次：母版／布局与本页是否重复绘制页眉、底线或旧页码；背景框是否盖住概述和正文；图片白边是否覆盖需要显示的框线；页码、标注与logo是否被后画对象遮挡。背景与装饰在对应内容下方，需要显露的边框和标注按实际关系放置，不能仅靠对象都存在就判定通过。

运行讲稿验证及一致性脚本。新交付或修改PPT备注时默认传 `--require-pure-speech-notes`：检查每页全部非空备注文本只包含canonical `paragraphs`，段数和文字一致；不加标题、时间、提示、来源、内部检查或分区标签，也不能将它们留在额外备注文本框。Word和PDF按各自用途核对完整正文，可有既定页号、独立提示和换行差异；PPT备注不因此允许额外内容。旧分区解析仅供历史回读兼容，未带严格参数的通过结果不认证纯备注。验证脚本不能替代科学判断及视觉检查。

## 实际渲染检查

1. 新报告用当前 Presentations 流程导出最终 PPTX，实际查看全部页面及配套PDF。总览用于全篇节奏，单页图用于裁剪、对齐和文字细节；与所选参考系列对照封面、正文及结束页。既有报告局部修改按下节确定复核范围，修改母版／布局时覆盖所有受影响页面。
2. 在上述范围内查看最终 PNG 和配套PDF页图，核查文字溢出、缺字、误换行、遮挡、图框对齐、标识和页脚重叠、重复图片，以及图证据是否仍清晰。特别检查窄栏中的单字末行、标点行首和数值单位分离；优先调整语义换行、栏宽与间距，保留准确文字，不为迁就版面删必要条件。表格和跨栏说明须按实际渲染下缘检查，静态高度估计只作提示。出现问题后修改并重新渲染，检查的是最终交付版本。
   新报告还与所选设计逐页并排比较区域比例、层次、图文位置、有效密度和原生编辑性。错误生成文字/曲线/品牌从准确数据和原素材纠正；原图回填等必要差异记录，不仅凭结构或像素相似宣称还原成功。
3. 新建或修改讲稿时读取当前 Documents 技能，运行其 `render_docx.py` 并查看相应页图。若 packaged renderer 失败先查看日志；有条件时可采用并记录实际 Word 或另一套可正确呈现中文的本地导出器（如本机 LibreOffice 无界面导出）。只读取 DOCX XML 或统计段落不能算视觉 QA。
4. 新建或修改纯讲稿 PDF 时用当前 PDF 流程渲染页图，检查大字可读性、关键词加粗、页号、段落续接和全文完整；新稿查看全部页，局部修改还检查受分页变化影响的后续页。结合文字提取检查内容，不能只看页数。
5. 有视频或原理动画时用当前可用的动态导出或播放验证媒体可见及计时。缺少可用的非界面验证方式时如实报告。静态 PNG 不能验证播放；确认是否内嵌及离线能否播放，不能仅凭关系文件存在宣称成功。

默认不用 computer use，优先使用当前工具的公开 API 程序化修改对象。确有必要编辑 OOXML 时，保留完整命名空间声明（包括属性值中的 QName 引用）及关系，按实际文件动态定位对象，不复制历史对象ID；修改后重新打开并实际渲染，使用PowerPoint包级功能时以实际PowerPoint验证接受和显示。XML 能解析不代表目标应用能接受该文件。此方法是受控实现选择，不是默认流程，也不要求其他环境采用本机Windows工具。

自动审查中的裁剪、图片面积和近边缘提示是待核查项。合法logo透明外围裁剪、承担辅助角色的小图或有意对齐，可依据原始素材、对象记录及最终渲染逐项关闭；保留理由和证据。不能为消除阈值提示而破坏原图，也不能一键忽略全部高等级提示。真实的裁切、缺字、不可读或遮挡须修复并复核。

## 局部修改与复核复用

- 沿用当前认可的论文、叙述、术语、品牌和素材，只修改用户指定的页面／对象及其实际影响项。改页脚、字号或图位不触发重新精读全篇、生成整套新预览或改写未受影响的讲稿。
- 修改前查看当前认可文件是否已满足要求，已一致时保持原文件，不为制造新版本重复改动。确需修改时记录正式文件及受影响范围；修改后检查页面数量、关系完整性、备注与必要结构。条件允许时比较包内改动部分、未改页内容或实际渲染哈希，证明局部修改没有波及其他页面。哈希仅用于确认相同内容，不能代替改页的视觉检查。
- 已有可靠视觉记录且最终渲染字节相同的页面可沿用原记录；目标页面以及分页、母版、布局、字体或公共组件改动所影响的页面须重新实际查看。没有足够证据限定范围时扩大复核范围，新报告仍查看全部页面。
- 每次修改同步对应PPT/PDF及受影响PNG，更新已有且受影响的总览或当前对照图；有交付清单、哈希记录或ZIP时一并更新，不为局部修改新增无关附件。仅改视觉且口述正文、页号及讲稿显示信息均未变时保留Word和大字稿原文件，核对备注正文仍与统一数据一致；相关正文、标题或页序改变时同步受影响的讲稿格式。
- 仅清理PPT备注中的非朗读内容时，逐页保留paragraphs原文并运行纯备注严格检查；正文、页序和可见幻灯片均未变时，保留现有Word、PDF、PNG、总览和对照图，不重建这些文件。检查PPT可正常打开，确认包内变化只涉及备注且幻灯片显示未变，再更新相关清单与ZIP。
- 当前成品、历史设计和复核记录分清版本，最终对照说明记录用户认可的必要差异。历史生图的保留与ZIP范围遵循“成品和工作材料”，不宣称未重新生成的图是本轮新设计。

## 依赖与限制报告

运行时使用 workspace dependency loader 和当下技能资源，避免复制旧会话中具体插件版本路径和旧对象 ID。导入造成母版、文字或图像丢失时先修复并重渲染；输出降级必须说明实际差异。

若某渲染工具或放映检查无法完成，说明缺少的检查及原因，仍保留已有成品和已完成的检查证据。不要把“未发现 XML 问题”“数值脚本通过”写成“所有页面已视觉核查”。最终回复只报告已完成的可观察结果及必要限制。
